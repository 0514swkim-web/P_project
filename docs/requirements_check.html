N4. 베이스라인: 단순 활성화 모드 같이 구현

12주차 · 1~2시간 · E단계 전에
왜계획서 실험 ②의 비교 기준이 "단순 활성화 방식(예: 손바닥 펴기 유지)"입니다. 설계한 클러치가 오작동을 얼마나 줄였는지 보이려면 같은 데이터로 둘 다 계산해야 합니다.
  • 문제: 지금 구조에서 손바닥은 그리퍼 열림이라, 클러치를 palm으로 바꾸면 역할이 겹칩니다.
  • 해결: 평가 전용 옵션 --clutch palm을 허용하고, 이때는 대기 상태에서만 손바닥 0.5초 유지를 활성화로 봅니다. 오작동률·활성화 실패율은 "활성화가 일어났는가"만 보므로 그리퍼 역할 충돌이 결과에 영향을 주지 않습니다.
  • 데이터: 비조작 trial은 이미 저장한 좌표로 다시 계산하면 됩니다(재촬영 불필요). 활성화 시도는 activate_palm 라벨을 수집 세트 2에 추가합니다.
  • 규칙 기반 vs 분류기도 같은 데이터로 비교합니다(계획서 실험 ②의 두 번째 기준).
python scripts\evaluate.py --data "data\raw\S*.csv" --clutch palm   # 베이스라인
python scripts\evaluate.py --data "data\raw\S*.csv" --clutch call   # 설계 클러치

N5. HaGRID 보강 같이 구현

12주차 · 2~3시간
  1. 라이선스·이용 조건 확인 후 출처 표기 방법을 기록합니다(계획서 4.3 "라이선스 조건 준수").
  2. 필요한 클래스만 받습니다: palm, fist, peace, call, rock, ok, like, one, no_gesture. 전체 데이터셋은 매우 크므로 일부만 받습니다.
  3. 주석에 손 랜드마크가 들어 있는지 먼저 확인합니다. 없으면 이미지에 MediaPipe(IMAGE 모드)를 돌려 21점을 뽑고, 우리 CSV 형식으로 저장합니다(scripts/import_hagrid.py, participant = HAGRID).
  4. HaGRID는 학습에만 쓰고 평가에는 쓰지 않습니다. 학습에 넣은 경우와 안 넣은 경우를 비교해 보강 효과를 보고합니다.

N6. 손이 여러 개일 때 같이 구현

12주차 · 1~2시간

계획서 예외 처리: "활성화한 손의 좌우 구분과 직전 위치를 저장하고, 같은 좌우이면서 직전 위치와 가장 가까운 손만 추적. 해당하는 손이 없으면 일시정지."

  • HandDetector를 num_hands=2로 바꾸고, 활성화 순간의 손(좌우 + 위치)을 기억하는 선택기를 pipeline.py 앞단에 둡니다.
  • 판별 시간과 FPS를 다시 측정합니다. 손 2개 탐지는 느려질 수 있으므로 30 FPS가 유지되는지 확인합니다.
  • 테스트: 가짜 손 두 개로 "다른 손이 들어와도 추적이 안 바뀜", "추적하던 손이 사라지면 PAUSED"를 검증합니다.

N8. 전체 성능 결과 정리 같이 구현

13주차 준비 → 15주차 분석 · 내 공통 업무
  1. 결과 수집 양식을 13주차 전에 팀에 배포합니다. 실험마다 참여자 ID, 조건, 시행 번호, 결과값, 비고를 같은 열 이름의 CSV로 받습니다.
  2. 집계 스크립트 scripts/summarize_results.py: 참여자별 비율 → 평균·t 분포 95% 신뢰구간(이미 있는 mean_ci 재사용). 연속 지표는 평균·표준편차.
  3. 비교 검정 (계획서 6.1 결과 보고): 손동작 vs 키보드는 참여자별 성공률·소요시간 중앙값으로 Wilcoxon 부호순위 검정을 하고, 리더 암(확장)은 Holm 보정을 합니다. 6명이면 최소 p값이 약 0.03이라 효과크기와 참여자별 결과를 함께 제시합니다. 검정은 scipy로 합니다(점검 중 requirements.txt에 빠져 있던 것을 발견해 scipy==1.17.1로 고정 추가함).
  4. 목표 달성표: 5개 실험의 지표 × 목표 × 결과 × 달성 여부를 한 장으로 만듭니다. 보고서와 발표에 그대로 씁니다.
