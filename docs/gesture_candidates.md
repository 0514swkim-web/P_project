# 제스처 후보 (초안 v0.1)

작성: 제스처 담당 · 2026-11-11 · **웹캠 확인·비조작 동작 데이터 비교 전 1차 후보**
근거: 과제계획서 3.2 ③(클러치 설계 원칙), 4.1(높이 모드 후보), 데이터 계획(HaGRID 보강)

## 1. 정해야 할 제스처

| 기능 | 역할 | 계획서 조건 |
|---|---|---|
| 그리퍼 열림 / 닫힘 | 활성 상태에서 집기·놓기 | 위치 기준점(손목·손바닥)이 흔들리지 않을 것 |
| **클러치** | 0.5초 유지로 조작 시작·정지 (토글) | **손 펴기·주먹처럼 흔한 모양 금지**, 그리퍼 제스처와 구분 |
| **높이 모드** | 유지하는 동안 손 상하 → 로봇 상하 | 그리퍼·클러치와 구분, 후보: 엄지만 편 손 / V자 |

비조작 동작 5종(오작동률 평가): 물 마시기, 머리 만지기, 손 흔들기, 휴대폰 보기, **물건 가리키기**

## 2. 비교 방법: 손가락 펴짐 패턴

손가락 5개(엄지·검지·중지·약지·소지)의 펴짐(1)/접힘(0)으로 보면, **다른 모양과 몇 개 손가락이 다른지(차이 수)** 가 클수록 헷갈릴 위험이 작다. 차이 1은 손가락 하나만 잘못 인식돼도 오판된다.

| 모양 (HaGRID 클래스) | 패턴 | 비고 |
|---|---|---|
| 손바닥 `palm` | 11111 | 흔한 모양 |
| 주먹 `fist` | 00000 | 흔한 모양 |
| 가리키기 `one` | 01000 | **비조작 동작(물건 가리키기)** |
| 엄지 척 `like` | 10000 | |
| V자 `peace` | 01100 | |
| 락 `rock` 🤘 | 01001 | |
| 샤카/전화 `call` 🤙 | 10001 | |
| OK `ok` | 00111 (엄지·검지 맞닿음) | 손가락 맞닿음 판별 필요 |

## 3. 제안

### 그리퍼: 손바닥(열림) / 주먹(닫힘)
- 서로 **5개 전부 다름** → 가장 안정적. 팀 초기 아이디어(주먹 쥐기·펴기 = 잡기·놓기)와도 일치.
- 흔한 모양이지만 **활성 상태에서만** 의미가 있으므로 문제없음 (활성화는 클러치가 막음).

### 높이 모드: V자 `peace` (1순위)
- 손바닥과 3, 주먹과 2 차이.
- 엄지 척 `like`는 **주먹과 차이 1**(엄지 하나) → 주먹(그리퍼 닫힘)과 헷갈릴 위험이 커서 2순위로 내림.
- 약점: 가리키기와 차이 1 → 활성 상태에서만 쓰이므로 영향 제한적.

### 클러치: 샤카 `call` 🤙 (1순위) / 락 `rock` 🤘 (2순위) / OK (3순위)

| 후보 | 손바닥 | 주먹 | 가리키기 | V자(높이) | 장점 | 약점 |
|---|---|---|---|---|---|---|
| **샤카 `call`** | 3 | 2 | **3** | 4 | 흔한 모양·가리키기와 모두 멀다 | 엄지 펴짐 판별이 가장 까다로움 |
| 락 `rock` | 3 | 2 | **1** | 2 | 엄지를 안 써서 판별이 쉬움 | 가리키기와 차이 1 (새끼손가락만 다름) |
| OK `ok` | 2 | 3 | 3 | 3 | 일상에서 드묾 | 손가락이 겹쳐 인식이 불안정할 수 있음 |

- 클러치는 **비조작 상태(대기)에서 감지**되므로 비조작 동작과 멀어야 함 → 가리키기와 먼 샤카를 1순위로 둠.
- 최종 확정은 계획서대로 **비조작 동작 데이터에서의 오인식 빈도 비교**로 결정.

## 4. 다음 확인 (웹캠 확보 후)

1. 각 후보를 손 각도·거리 바꿔가며 해보고 MediaPipe 인식이 흔들리지 않는지 확인
2. 특히 **엄지 펴짐 판별**(샤카, 엄지 척)이 안정적인지 확인
3. 비조작 동작 5종을 하면서 클러치 후보가 잘못 감지되는 횟수 비교 → 클러치 확정
4. HaGRID에서 `palm`, `fist`, `peace`, `call`, `rock`, `ok`, `one`, `like`, `no_gesture` 데이터 확보
