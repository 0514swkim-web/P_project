# 튜닝 기록 (규칙 판별기 · 클러치 상태 머신)

실제 손으로 확인하면서 **무엇이 틀렸고, 왜 틀렸고, 어떻게 고쳤는지**를 남기는 문서.
보고서의 "판별 규칙 설계·개선 과정"과 발표 Q&A("임계값은 어떻게 정했나요?")의 근거로 쓴다.

> 여기 숫자는 **튜닝용 점검**이다. 고른 프레임 몇 개를 다시 판정한 것이라 정확도 지표가 아니다.
> 보고서의 정확도·오작동률은 `collect_landmarks.py`로 모은 데이터와 `evaluate.py` 결과만 쓴다.

## 기록 방법

1. `live_demo.py`로 녹화할 때 **`--log`를 같이** 켠다. 영상은 눈으로 보는 용, CSV는 수치 분석용.
   ```powershell
   python scripts\live_demo.py --record recordings\T01_A_basic_indoor.mp4 --log recordings\T01_A_basic_indoor.csv
   ```
   CSV에는 프레임마다 모드·제스처·신뢰도와 손가락 원시 값(엄지 각도·거리, 손가락 각도, OK 거리)이 들어간다.
2. 문제를 찾으면 아래 양식으로 **문제 → 원인(수치) → 수정 → 수정 전후 비교 → 남은 문제** 순서로 적는다.
3. 수정에 쓴 실측값은 테스트로도 남긴다 (`tests/test_rules.py`의 `REAL_THUMBS` 처럼). 나중에 임계값을 또 바꿔도 이번 손 모양이 깨지지 않는지 바로 확인된다.
4. 영상·CSV는 `recordings/`(git 제외, 얼굴 포함)에 둔다. 이 문서에는 수치만 옮긴다.

### 발견한 문제와 수정

#### P1. V자가 `none`과 `peace` 사이를 깜빡임 (영상 A 71~75초)
- **증상**: 패턴은 거의 매번 `01100`으로 맞는데 신뢰도가 0.14~0.35 → 0.3 컷에 걸려 `none`.
- **원인**: 엄지 거리 0.49~0.56이 임계값 0.6에 바짝 붙어 있었다. 신뢰도 = 가장 애매한 손가락의 여유라서 엄지 하나가 전체를 깎음.
- **실측 (엄지 거리, 손바닥 크기 = 1)**:

  | 엄지 상태 | 손 모양 | 엄지 거리 | 엄지 각도 |
  |---|---|---|---|
  | 접힘 | V자, 락, 검지, 주먹 | 0.24 ~ 0.56 | 150 ~ 160 |
  | 펴짐 | 손바닥, 샤카, 엄지 척, OK | 0.97 ~ 1.45 | 154 ~ 173 |

  → 두 그룹 사이(0.56 ~ 0.97)가 비어 있다. **엄지 각도는 접힘·펴짐 모두 150 이상이라 구분에 거의 쓸모가 없다**는 것도 확인.
- **수정**: `RuleConfig.thumb_away_dist` 0.6 → **0.75** (두 그룹 사이값).

#### P2. 엄지 신뢰도 계산 오류 (주먹이 `none`, 영상 B 43~60초)
- **증상**: 주먹 패턴 `00000`은 맞는데 신뢰도 0.03~0.11 → 거의 매번 `none`.
- **원인**: 엄지는 "각도 통과 **AND** 거리 통과"일 때만 펴짐인데, 신뢰도는 두 조건 여유의 최솟값으로 계산했다. 주먹에서 엄지 각도가 141~143으로 임계값 140에 붙어 있어서, **거리로 확실히 접혔는데도(0.45~0.57) 통과한 각도의 여유가 신뢰도를 깎았다.**
- **수정**: `thumb_state()` 분리. 각 조건을 부호 있는 여유(+ 통과, − 미통과)로 바꾸고 `|min|`을 쓴다.
  - 펴짐(둘 다 +): 덜 통과한 쪽이 여유
  - 접힘(하나라도 −): **가장 크게 못 넘은 쪽**이 접힘의 근거

#### P3. 엄지를 편 V자가 `none` (영상 D 31~46초)
- **증상**: 시나리오 녹화에서는 V자를 엄지를 편 채로 했다. 패턴 `11100`, 엄지 거리 0.84~1.87(확실히 펴짐) → 표에 없는 패턴이라 `none`.
- **판단**: 같은 사람도 녹화마다 엄지를 다르게 했다. 다른 참여자도 그럴 것. `11100`을 쓰는 다른 제스처는 없다.
- **수정**: `GESTURE_PATTERNS`에 "상관없음(None)" 도입, V자 = `(None, 1, 1, 0, 0)`.
  - 신뢰도도 **그 제스처를 정하는 데 쓴 손가락만으로** 계산하도록 변경 (V자에서 엄지가 애매해도 V자 판정은 확실).
  - 가짜 데이터의 none 예시 중 `11100`을 `11110`으로 교체 (`synthetic.py`).

#### P4. OK가 한 번도 인식 안 됨 (영상 A 94~97초)
- **증상**: 패턴 `10111`, OK 거리 0.46~0.61인데 임계값이 0.25라 OK 조건 자체를 통과 못 함.
- **실측**: OK 0.46~0.61 / 중지·약지·소지가 펴진 다른 손(손바닥) 1.33 이상.
- **수정**:
  - `ok_touch_dist` 0.25 → **0.8**.
  - OK 조건에 **엄지 펴짐** 추가. 없으면 엄지·검지를 둘 다 접은 손(`00111`)도 두 끝이 가까워 OK가 됨 (테스트에서 발견). 실측 OK 엄지는 거리 0.97~1.15로 펴짐.
  - OK 신뢰도에서 반쯤 굽은 검지(141~142도)는 뺌.
  - 가짜 OK 손을 실측 모양으로 수정 (엄지를 내밀어 검지 끝과 맞닿음).

#### P5. 0.1초 인식 끊김에도 바로 `PAUSED` → 조작 대부분이 일시정지 상태 (영상 D)
- **증상**: 시나리오 96초 중 20~80초 대부분이 `PAUSED`. 그동안 한 이동·V자 높이·그리퍼 동작이 전부 반영 안 됨.
- **원인**: 손이 한 프레임만 안 보여도 즉시 `PAUSED`, 재개는 클러치 필요. 영상 D에서 0.07~0.4초 인식 끊김이 **13번**(영상 A 7번). 82초·90초의 0.1~0.2초 끊김 직후 실제로 `PAUSED`.
  (20초 부근은 손을 화면 밖으로 뺀 진짜 소실이라 정상 동작.)
- **수정**: `ControlConfig.lost_grace_s = 0.3`.
  - 끊기는 순간 **바로 위치 고정**(hold) → 로봇은 즉시 멈춤 (안전 원칙 그대로).
  - 0.3초 안에 손이 돌아오면 모드 유지, 클러치 다시 안 해도 됨.
  - 0.3초 넘게 이어지면 기존대로 `PAUSED`.
- **팀 공유 필요**: 계획서의 "손 소실 → 일시정지" 규칙을 "즉시 정지, 0.3초 넘으면 일시정지"로 구체화한 것.
