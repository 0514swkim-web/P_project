# 실내 녹화 가이드 (튜닝 #2용 · ZIO 웹캠 30 FPS)

11/21 야외 녹화(10 FPS, A·B·D만)에 이어 **실내·ZIO 웹캠·30 FPS**로 A~F를 녹화한다.
목적은 **규칙 임계값 튜닝과 클러치 후보 비교**다. 보고서용 정확도·오작동률 수치는 이 녹화가 아니라 `collect_landmarks.py` 수집 데이터로 낸다.

전체 약 30분. 아이패드로 이 페이지를 보면서 진행한다.

---

## 0. 준비 (5분)

**장소·카메라**
- [ ] 밝은 실내. 창문을 등지지 말 것(역광이면 손이 어두워짐). 배경은 단순하게
- [ ] ZIO 웹캠을 고정(노트북 화면 위 또는 거치대). 렌즈 높이 ≈ 가슴~손 높이
- [ ] 손은 카메라에서 **50~80cm** (C 구간만 거리를 바꿈)
- [ ] 준비물: 컵, 휴대폰, 가리킬 물건 하나 (E 구간)

**실행 확인**
```powershell
.venv\Scripts\python scripts\live_demo.py --camera 1
```
- [ ] 화면 FPS가 30 근처인지
- [ ] `d` 키로 **손가락 상세 막대**를 켜 둔다 (영상에도 수치가 같이 찍힘)
- [ ] 확인 끝나면 `q`로 닫고 아래 녹화 명령으로 다시 실행

**녹화 명령 (구간마다 이름만 바꿈)**
```powershell
.venv\Scripts\python scripts\live_demo.py --camera 1 --record recordings\T01_A_indoor.mp4 --log recordings\T01_A_indoor.csv
```
- `--record`(영상, 눈으로 보는 용)와 `--log`(CSV, 수치 분석용)를 **반드시 같이**. 11/21에는 `--log`가 없어서 화면을 직접 읽어야 했다
- 녹화 시작 = 실행, 녹화 끝 = `q`
- **구간마다 파일 이름을 바꾼다** (`T01_A_indoor` → `T01_B_indoor` → `T01_C1_near` ...). 11/24 같은 이름으로 계속 실행해서 A·B가 덮어써졌다. 지금은 같은 이름이면 `_2`, `_3`이 자동으로 붙지만, 이름이 구간을 알려 줘야 분석이 쉽다

**모든 구간 공통 규칙**
1. **손 모양 사이에는 손을 화면 밖으로 2초 뺀다.** CSV에서 `hand_detected = 0` 구간으로 자동으로 나뉘어서, 어느 프레임이 어떤 손 모양인지 따로 적지 않아도 된다
2. 아래 표의 **순서를 지킨다** (순서 = 라벨)
3. 유지하는 동안 손을 **살짝** 기울이거나 좌우로 천천히 움직인다 (완전히 멈춘 손만 있으면 튜닝에 도움이 안 됨)
4. 기본은 **오른손**
5. 순서가 꼬이면 손을 내리고 그 손 모양부터 다시 한다. 꼬인 곳은 아래 기록 칸에 적는다

## C. 거리·각도·조명 — 4개 파일 (약 6분)

조건이 바뀌어도 판별이 유지되는지 본다(계획서 "조건별 정확도"의 사전 점검). 손 모양은 **손바닥 → 주먹 → V자 → 샤카** 4개만, 각 **4초 → 손 빼고 2초**. 조건마다 파일을 따로 만든다.

| 파일 | 조건 | 방법 |
|---|---|---|
| `T01_C1_near` | 가까이 | 손을 카메라에서 약 **40cm** (권장 하한 50cm보다 가까이) |
| `T01_C2_far` | 멀리 | 약 **120cm** (팔을 뻗거나 의자를 뒤로) |
| `T01_C3_side` | 옆 각도 | 80cm, 손을 카메라 기준 **약 30° 옆**으로 돌림 |
| `T01_C4_dim` | 어둡게 | 80cm 정면, **조명 일부 끄기**. 화면 FPS가 몇까지 떨어지는지 기록 |

(여유 있으면) `T01_C5_left`: 80cm 정면, **왼손**으로 A의 1~4번.

## D. 조작 시나리오 — `T01_D_indoor` (약 2분)

실제 쓰는 흐름대로 상태 머신(클러치·모드 전환·손 끊김)을 본다. 클러치는 기본값 샤카(`call`). **같은 흐름을 2번** 반복한다.

1. 손을 편하게 둔다 → 화면 모드 `IDLE`
2. **샤카 0.5초 유지** → `PLANAR`로 바뀌는지 (클러치 게이지가 차는 것 확인)
3. 손바닥으로 좌우·앞뒤 천천히 이동 (5초)
4. **주먹** (잡기) → 그리퍼 `CLOSED`, 바뀌는 순간 `HOLD` 표시
5. **V자** → `HEIGHT`, 손을 위로 올렸다 내리기 (5초)
6. V자 풀고 주먹 유지 → `PLANAR`로 돌아오는지
7. **손바닥** (놓기) → `OPEN`
8. **손 끊김 짧게**: 손을 화면 밖으로 **0.3초 미만** 뺐다 넣기 → 모드 유지되는지
9. **손 끊김 길게**: 손을 **1초 이상** 뺐다 넣기 → `PAUSED`로 바뀌는지
10. 샤카 0.5초 → 다시 `PLANAR`, 다시 샤카 0.5초 → `IDLE`

## E. 비조작 동작 — `T01_E_indoor` (약 4분)

평소 동작에서 클러치 후보가 **잘못 감지되는 횟수**를 본다. 클러치를 의식하지 말고 **평소처럼** 한다. 각 동작 **4회**, 회마다 손을 내려 2초 쉰다.

| 순서 | 동작 | 준비물 |
|---|---|---|
| 1 | 컵 들어 물 마시고 내려놓기 | 컵 |
| 2 | 머리나 얼굴 편하게 만지기 | – |
| 3 | 카메라 쪽 누군가에게 인사하듯 손 흔들기 | – |
| 4 | 휴대폰 들어 화면 보다가 내려놓기 | 휴대폰 |
| 5 | 책상 위 물건 손가락으로 가리키기 | 물건 |
| 6 | (추가) 1분 동안 평소처럼 앉아 있기: 턱 괴기, 키보드 치기, 머리 긁기 등 자유롭게 | – |

- 한 번만 녹화하면 된다. CSV에 프레임별 제스처가 남아서, 분석할 때 **후보(call·rock·ok·palm)별로 상태 머신을 다시 돌려** "이 후보가 클러치였다면 몇 번 잘못 켜졌을까"를 비교할 수 있다
- 내가 클러치를 알고 하는 동작이라 실제보다 덜 잘못 켜질 수 있다. 보고서용 오작동률은 다른 참여자 데이터로

## F. 클러치 활성화 — 후보별 4개 파일 (약 6분)

일부러 켤 때 **잘 켜지는지, 얼마나 걸리는지** 본다. E(잘못 켜짐)와 합쳐서 클러치를 고른다. 후보마다 `--clutch`를 바꿔 따로 녹화한다.

```powershell
.venv\Scripts\python scripts\live_demo.py --camera 1 --clutch call --record recordings\T01_F_call.mp4 --log recordings\T01_F_call.csv
```

| 파일 | `--clutch` | 횟수 |
|---|---|---|
| `T01_F_call` | `call` (샤카, 1순위) | 10회 |
| `T01_F_rock` | `rock` (락, 2순위) | 10회 |
| `T01_F_ok` | `ok` (OK, 3순위) | 10회 |
| `T01_F_palm` | `palm` (손바닥, 베이스라인) | 10회 |

1회 진행:
1. 손을 편하게 내려놓고 2초
2. 클러치 모양 → **켜질 때까지 유지** (모드가 `PLANAR`로 바뀌면 성공)
3. 3초 안에 안 켜지면 실패로 보고 손을 내린다
4. 켜졌으면 같은 클러치로 다시 끄고 손 내리기
