## 1. 목적과 실험 목록

계획서 6.1의 실험 5개를 같은 절차·기록 형식으로 진행하기 위한 문서입니다. 실험 ②는 제스처 담당 담당이고, 나머지는 각 담당자가 세부 절차를 확인합니다.

| 실험 | 담당 | 비교 기준 → 비교 대상 | 주요 지표 | 목표 | 참여자 |
|---|---|---|---|---|---|
| ① 떨림 안정화 | 팀원A | 필터 미적용 → 이동평균·데드존·One Euro | 정지 시 표준편차(mm), 추가 추종 지연(ms), 미세 이동 반영률 | 흔들림 70%↓, 지연 50ms 이내, 반영률 90%↑ | 팀원 (녹화) |
| ② 조작 의도 인식 | **제스처 담당** | 단순 활성화(손바닥 유지)·규칙 기반 → 클러치·학습 분류기 | 오작동률, 정확도·F1, 활성화 실패율 | 5%↓, 95%↑, 10%↓ | 선정·학습용, 평가용 |
| ③ 실시간성 | 팀원B | 최적화 전 → 최적화 후 | 종단 간 지연, 처리 지연 p95, FPS | 250ms↓(평균), 100ms↓(p95), 30 FPS↑ | 팀원 |
| ④ 작업 수행 | 팀원C | 키보드 → 손동작 (리더 암: 확장) | 집어 옮기기 성공률, 소요 시간 | 성공률 80%↑ (실물) | 평가용 |
| ⑤ 안전 기능 | 팀원C | – | 실제 정지까지 시간, 정지 실패 | 0.5초 이내, 실패 0회 | 팀원 |

### 2.2 모집·선정

- 모집 방법: `[확인 필요: 지인 / 학과 공지 / 사례 여부]`

## 4. 데이터 기록 규칙

- **영상은 저장하지 않고** 손 랜드마크 좌표(21점 × x, y, z)와 메타 정보만 CSV로 저장합니다 (`scripts/collect_landmarks.py`).
- 파일: `data/raw/<ID>_<session>_<condition>_<날짜>.csv` (스크립트가 자동 생성)
- 데이터에는 **ID만** 씁니다. 이름·연락처와 ID 대응표는 동의서와 함께 **오프라인**으로 보관하고, 데이터 폴더·클라우드·AI 도구에 올리지 않습니다.
- 데이터 보관 장소: `[확인 필요: 로컬 + 팀 클라우드 여부]` (현재 `C:\Dev`가 Google Drive와 동기화됨 → 동의서에 반영)
- 세션 기록지(5.4)에 날짜, 장소, 조건, 진행자, 특이사항을 남깁니다.

## 5. 세션 절차

### 5.1 데이터 수집 세션 — 팀원·선정·학습용 (약 30분)

| 순서 | 내용 | 명령 / 분량 | 시간 |
|---|---|---|---|
| 1 | 설명·동의 | 동의서 서명 | 5분 |
| 2 | 연습 | 각 제스처를 화면 보며 1회씩 | 3분 |
| 3 | 제스처 세트 (조건별) | `--labels` 기본값: palm, fist, peace, call, rock, ok, like, one, none / **라벨당 5 trial × 약 3초** | 조건당 약 10분 |
| 4 | 비조작 동작 | nonop 5종 **× 4회** | 5분 |
| 5 | 의도적 활성화 | activate_call / rock / ok / palm **각 10회** | 7분 |

```powershell
python scripts\collect_landmarks.py --participant S01 --condition bright_front --camera 1
python scripts\collect_landmarks.py --participant S01 --camera 1 --labels nonop_drink,nonop_head,nonop_wave,nonop_phone,nonop_point,activate_call,activate_rock,activate_ok,activate_palm
```

### 5.2 평가 세션 — 평가용 (1인 1회, 약 1~1.5시간, 계획서 14주차)

| 순서 | 내용 | 실험 | 시간 (예상) |
|---|---|---|---|
| 1 | 설명·동의, 안전 안내 (비상정지 위치) | – | 5분 |
| 2 | 제스처 세트 (조건 `bright_front` 필수 + 1개) | ② 정확도 | 15분 |
| 3 | 비조작 동작 5종 × 4회 | ② 오작동률 | 10분 |
| 4 | 의도적 활성화: 확정 클러치 10회 + 베이스라인(손바닥) 10회, **순서 교차** | ② 활성화 실패율 | 7분 |
| 5 | 휴식 | – | 3분 |
| 6 | 작업 수행: 키보드 / 손동작, **방식 순서 교차**, 방식별 연습 5분, 목표 5곳 × 4회 | ④ | 40~50분 `[파일럿으로 확인]` |
| 7 | 설문 (사용 편의, 피로도) `[확인 필요: 문항]` | – | 5분 |

- 순서 교차: 참여자 번호가 홀수면 A→B, 짝수면 B→A (활성화: 클러치↔베이스라인, 작업: 키보드↔손동작)
- 작업 수행 20회 × 2방식에 90초 제한이 있어 세션이 1.5시간을 넘을 수 있습니다. **파일럿(13주차)에서 시간을 재고 조정합니다.**

### 5.3 진행 스크립트 (실험 ②)

**제스처 세트**
> "화면에 나오는 손 모양을 하고, 제가 '시작'이라고 하면 3초 동안 그대로 유지해 주세요. 손을 조금씩 움직이거나 살짝 기울여도 괜찮습니다."

**비조작 동작** — 클러치를 의식하지 않게 합니다.
> "지금부터는 로봇 조작이 아니라 평소 행동을 기록합니다. 로봇이나 화면은 신경 쓰지 마시고, 제가 말하는 행동을 평소처럼 해 주세요."

| 라벨 | 지시 | 준비물 |
|---|---|---|
| `nonop_drink` | "컵을 들어 물을 마시고 내려놓아 주세요." | 컵 |
| `nonop_head` | "머리나 얼굴을 편하게 만져 주세요." | – |
| `nonop_wave` | "카메라 쪽 누군가에게 인사하듯 손을 흔들어 주세요." | – |
| `nonop_phone` | "휴대폰을 들어 화면을 보다가 내려놓아 주세요." | 휴대폰 |
| `nonop_point` | "책상 위 물건을 손가락으로 가리켜 주세요." | 물건 |

**의도적 활성화**
> "손을 편하게 내려놓고 계시다가, 제가 '지금'이라고 하면 [클러치 / 손바닥] 모양을 해서 로봇을 켜 주세요."

- 진행자는 녹화(SPACE) 직후 "지금"을 말하고, 3~5초 뒤 녹화를 멈춥니다.

## 6. 판정 기준·지표 정의 (실험 ②)

| 지표 | 정의 | 단위 |
|---|---|---|
| 오작동 | 비조작 동작 1 trial 중 활성화(PLANAR/HEIGHT)가 **한 번이라도** 일어남 | trial |
| 오작동률 | 참여자별 (오작동 trial / 비조작 trial) → 참여자 평균 | % |

| 제스처 정확도·F1 | 평가셋 프레임 단위, 명령 제스처별. 비조작은 오작동률로 따로 평가 | % |
| 판별 시간 | 특징 추출 + 판별, 프레임당 | ms (목표 5 미만) |

## 7. 분석 계획 (계획서 6.1 결과 보고)

- 비율 지표(오작동률, 활성화 실패율, 성공률): **참여자별 비율**을 단위로 평균과 t 분포 95% 신뢰구간 (같은 사람의 시행은 독립이 아니므로)
- 연속 지표: 평균 ± 표준편차
- 방식 비교(④ 손동작 vs 키보드): 참여자별 성공률·소요 시간 중앙값으로 **Wilcoxon 부호순위 검정**. 리더 암(확장)은 **Holm 보정**한 탐색적 분석
- 6명이면 최소 p값이 약 0.03이라 검정력이 낮으므로 **효과크기와 참여자별 결과를 함께** 제시
- 실험 ②: 클러치 vs 베이스라인, 규칙 기반 vs 분류기를 같은 평가 데이터로 비교 (`evaluate.py --clutch`, `--model`)
- 시뮬레이션과 실물 결과는 판정 기준이 달라 따로 보고

## 8. 안전 수칙 (실물 로봇 사용 시)

- 물리 비상정지 스위치 없이 실물 로봇을 움직이지 않습니다.
- 진행자 1명은 실험 내내 비상정지 스위치 옆에 있습니다.
- 낮은 작업 높이와 작업대 완충재를 씁니다 (전원 차단 시 팔이 처질 수 있음).
- 참여자는 로봇 작업 반경 밖에 앉습니다 `[확인 필요: 거리]`.
- 재통전 시 자동 재개 금지 (수동 해제 후 재시작).

## 9. 파일럿과 버전 동결 (13주차)

1. 팀 외 1~2명으로 평가 세션 전체를 리허설합니다 (시간, 지시문 이해도, 장비 문제).
2. 파일럿 결과로 세션 시간·지시문·제한 시간(90초)을 조정합니다.
3. **실험용 버전 확정**: 코드 커밋 태그와 설정값(클러치, `stable_frames`, 임계값, 모델 파일)을 기록하고, 평가 세션 동안 바꾸지 않습니다.
4. 파일럿 참여자 데이터는 최종 평가에서 제외합니다.
